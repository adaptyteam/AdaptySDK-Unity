# The SDK harness

`Assets/SdkHarness/` is a scene with nothing in it but a `RuntimePipelineManager` (port pinned to 7900) and `AdaptySdkHarness`, which registers four `[CliCommand]`s in the player: `harness_activate`, `harness_call` (any public static `Adapty` or `AdaptyUI` method by name, arguments as a JSON object keyed by parameter name, the overload chosen by exactly that key set — an argument written as `"$GetFlow"` or `"$GetPaywallProducts[0]"` is the object the last successful call of that method handed back, which is how a flow reaches `GetPaywallProducts` and a product reaches `MakePurchase`; do not paste a returned model's JSON back instead, the SDK never reads a response model from JSON — a product goes out as `AdaptyPaywallProductRequest`, its own shape — so the dump has no reader and fails on the subscription offer while proving nothing), `harness_events` (what the listeners received, decoded), `harness_status`. It exists because the desktop suite feeds the SDK fixtures, and only a player can say whether the C# layer decodes what the *native* SDK actually returns, on IL2CPP, after stripping — which is why `link.xml` beside it keeps the whole SDK assembly, and why every callback shape with a value-type payload (`bool`, `AdaptyLogLevel`) is instantiated once in `AotHints` so IL2CPP compiles it. Commands run on the request thread and post the call to the main one, because the SDK delivers callbacks through `SynchronizationContext.Post` and a main-thread wait would deadlock every call; the wait budget (`--timeout_ms`, 20 s by default) stays under the scene's 120 s request timeout; the first calls after an activation with a customer id have taken 8–20 s while the backend merged the profile, so give those more. It does not expose the raw bridge JSON — the request/response bytes live inside `AdaptyRequest` — only what the SDK decoded. It activates once per process: relaunch the app for another activation. The scenario is data, not code, so a new test is a new payload and needs no rebuild. The screen is not empty for the person watching: a UI Toolkit ledger built in code (the only asset is `SdkHarnessPanel.asset` with its `unity-theme://default` theme) lists every request (→), reply (←), failure (×), late reply (← or × with "late" — the command already returned as timed out; the object still becomes the handle) and delivered event («) with its timestamp, so a run can be followed on the simulator and read back when the agent is stuck.

## Build and run

Build it with its own `harness_build` command (`Assets/SdkHarness/Editor/`), not `unity command build`: the CLI sends a single `--scenes` value as a string, the server binds that to an empty array and silently builds `EditorBuildSettings` instead, and `dry_run` reports a nonexistent scene as valid. A player build holds the main thread for minutes, so submit it detached and wait on the job:
```bash
unity command harness_build --detach                          # scenes = Assets/SdkHarness/SdkHarness.unity, iOS, Development, SimulatorSDK
unity job wait <job-id> --timeout 1500
xcrun simctl uninstall <udid> com.adapty.adaptydemoapp      # or the previous install's descriptor passes for readiness
osascript -e 'tell application "Xcode"
  set ws to open "'"$PWD"'/ios-harness-build/Unity-iPhone.xcworkspace"
  repeat until loaded of ws
    delay 1
  end repeat
  set active scheme of ws to (first scheme of ws whose name is "Unity-iPhone")
  set active run destination of ws to (first run destination of ws whose name is "iPhone 17 Pro (26.5)")
  run ws
end tell'
APP=$(xcrun simctl get_app_container <udid> com.adapty.adaptydemoapp app)   # --runtime-path takes this DIRECTORY, not the descriptor file inside it
unity command harness_activate --runtime-path "$APP"
unity command harness_call --runtime-path "$APP" --method GetFlow --args '{"placementId":"rt.RegTestPaywall1","fetchPolicy":"Default","loadTimeout":10}'
```

Open the **workspace**: External Dependency Manager writes a Podfile, and the bare `.xcodeproj` fails at link with `framework 'Pods_UnityFramework' not found`. Xcode runs it, not `xcodebuild`, because of purchases: `harness_build` files `Assets/SdkHarness/AdaptyDemo.storekit` in the project (as `text`, with no target membership — Xcode offers nothing else as a configuration) and selects it in the scheme's Run options, and Xcode syncs that configuration into the simulator through its Instruments service when it launches the app, so `storekitd` serves the products locally and `MakePurchase` raises Xcode's confirmation sheet instead of the Apple Account sign-in. Nothing else performs that sync: `xcodebuild` (build or test) ignores the scheme option, and an `SKTestSession` opened from the app, or from an `xcodebuild test` host, is refused by `storekitd` as not entitled. Xcode names its destination by device and runtime (`iPhone 17 Pro (26.5)`) and boots that simulator even when another one is up, so address the device by UDID (`xcrun simctl list devices`) rather than `booted`. The sheet and the "You're all set" alert after it take a tap each; the `ios-storekit-purchase` skill (`.claude/skills/ios-storekit-purchase/`) says which log line means which window is up and where its button is, so a purchase needs no screenshot. On the harness that is: `harness_activate`, `GetFlow` and `GetPaywallProducts` first, then `harness_call --method MakePurchase --args '{"product":"$GetPaywallProducts[0]"}' --timeout_ms 90000` in the background — it returns only after the alert's OK — and `GetProfile` to see the access level. The descriptor with the port and token appears next to the app's `Data/` once the server is up, which makes its existence the readiness signal.

## What the commands can and cannot take

Some argument shapes have no JSON reader in the SDK and get one in the harness: a type whose instances are public static members (`AdaptyPlacementFetchPolicy`, `AdaptyExternalAttributionProvider`) is addressed by member name, and a string for a type with a one-string constructor becomes that instance (a provider by identifier); a `TimeSpan` parameter is taken as seconds (inside an object it is Newtonsoft's `"00:00:10"`); enums go through the SDK's own converter as strings; a request-only model with a nested `Builder` (`AdaptyProfileParameters`, `AdaptyConfiguration`) is built from a JSON object — constructor arguments by parameter name, every other key a `Set<Key>` call, `customAttributes` an object of string or number values — so `UpdateProfile` takes `{"param":{"firstName":"A","customAttributes":{"plan":"pro","score":3}}}`. Models with public fields and a parameterless constructor (`AdaptyUICreateFlowViewParameters`, `AdaptyUIDialogConfiguration`, `AdaptyPurchaseParameters`) read as plain JSON. Not reachable this way: `AdaptyCustomAsset` values (factory methods, no members), custom tags and timers on `CreateFlowView` (setters, not fields), `SetFallback` (needs a file in the app), and the legacy onboarding events (`IAdaptyOnboardingsEventsListener` is obsolete; the harness does not register it). `Activate` is refused by `harness_call` because activation is once per process — `harness_activate` builds the configuration, with `--configuration` for the Builder keys it has no flag for. Only iOS: `harness_build` targets the simulator SDK, an Android build is not written. The player's own command set adds `console`, `runtime_status`, `simulate_pointer`; `eval` is registered there but compiled out on anything that is not the Editor or a standalone development build, which is why the harness's commands are compiled ones. Nothing here runs on a real device without a package change: the runtime server writes its descriptor into the app bundle and stops itself when that write fails.
